## 第二优先级：电脑 AI 智能体远程联动（P1）

**目标：用户通过手机提交开发任务，由电脑上的 AI 智能体执行并回传结果。**

基础功能清单（数据模型与安全边界已在 `docs/REMOTE_AGENT_ARCHITECTURE.md` 设计，未开发）：

1. 手机创建开发任务（指定项目和执行目标）。
2. 选择获授权的智能体（AgentAdapter 按工具能力适配）。
3. 查看执行状态 / 代码修改摘要 / 测试结果 / 失败原因（TaskRun + Event 流）。
4. 审批后继续（敏感操作必须 Approval，复用 proposal-repository 模型）。
5. 暂停或取消任务（软超时 10min / 硬超时 30min）。
6. 接收执行结果通知。

### 现有工具集成能力核实（必须先做，不能假定）

| 工具 | 核实要求 | 当前认知 |
|---|---|---|
| Codex | 是否有开放的远程控制 API / headless 执行接口 | 待核实——只有确认真实可用接口才可适配 |
| WorkBuddy | 是否有外部可调用的任务/对话 API | 待核实 |
| 其他 | 没有公开接口的工具，不可宣称可自动控制 | 默认不可 |

### 安全边界（全部满足才可启用，详见 REMOTE_AGENT_ARCHITECTURE.md S1–S7）

- 身份认证（Device 绑定 + 密钥对 + 撤销列表）。
- 权限隔离（只读/普通写/敏感三级；敏感级必须用户批准）。
- 电脑端只出站连接（outbound-only），不开放公网入站端口。
- 全链路审计（append-only Event，可导出）。
- Agent 从不冒充用户；失败如实上报。

**退出门槛**：真机 + 真电脑双端验收通过（含离线重连、取消、权限审批、审计导出）。

## 第三优先级：Jev 信息分析（P1）

**定位：Jev 作为统一结构化判断引擎——负责判断，不直接掌握高风险执行权限。**

应用场景：

1. 活动检索（哪些活动值得去）。
2. 副业机会评估。
3. 求职信息分析。
4. 闲鱼订单异常分析。
5. 自媒体数据变化解读。
6. 任务优先级判断。
7. 来源可信度分析。
8. 信息与已有项目的自动匹配。

**输出契约（每条判断必须包含）**：

| 字段 | 说明 |
|---|---|
| 输入信息 | 被判断的原始内容 |
| 来源 | 信息的出处与获取时间 |
| 判断结果 | 结构化结论（评分/分类/排序） |
| 可信依据 | 支持判断的具体证据 |
| 证据缺口 | 缺什么才能更确定 |
| 风险提示 | 判断可能出错的方向 |
| 下一步建议 | 用户可执行的验证动作 |

**硬规则**：证据不足时允许并鼓励 **ABSTAIN**（弃权），不允许强行给出高置信结论；Jev 的判断只是建议，执行权永远在用户或经过批准的智能体。

**退出门槛**：至少 3 类场景（如活动/副业/求职）跑通「输入→判断→证据→缺口→建议」完整输出，且与现有 trust/dedupe/eligibility 层集成（search/trust/dedupe 永不直接调模型的原则不变）。

## 第四优先级：智能记忆（P2）

**目标：构建可检索的个人记忆库，导入其他 AI 智能体的工作经验。**

支持导入：

1. 历史对话摘要。
2. 项目说明。
3. 技术经验。
4. 任务进度。
5. 失败记录。
6. 个人工作偏好。
7. 文档知识。

**硬规则**：

- 保留每条记忆的**来源、版本、时间与去重记录**。
- 支持用户**审查、纠错和删除**。
- **不得自动将全部历史内容判断为真实**——导入的内容默认标注来源与置信，与 Jev 判断层联动核实。
- 检索优先（先复用现有 Notes/Opportunity 检索能力），不重复造搜索引擎。

**退出门槛**：至少 2 类来源（如对话摘要 + 项目说明）完成导入→去重→检索→纠错闭环。

## 第五优先级：业务自动化（P3）

逐步支持（每项独立验收，先人工确认规则再自动化）：

1. 自媒体数据跟踪与复盘。
2. 闲鱼订单与异常监测。
3. 合规数字商品交付工作流。
4. 副业信息筛选。
5. 行程规划。
6. 任务自动匹配。
7. 跨项目的经验积累。

**副作用红线**：所有涉及付款、发货、账户操作、对外发布的操作，必须逐项检查平台规则、用户授权和执行权限；未经明确批准不自动执行；Jev/Agent 只准备，用户决定。

## 变更管理

- 每阶段开始：读本文件 + `docs/workbench/V23_EXECUTION_STATE.md` → 核对 Git 状态 → 只选当前优先级工作包。
- 已 REAL 的能力不得重复开发；新功能先进 Issue，不提前干扰当前验收。
- 每阶段结束：单测 + 构建通过 + 真实使用证据 + 状态文档更新；未测试如实写 NOT_TESTED。
- 阶段验收未通过，不把下一阶段标 DONE。
