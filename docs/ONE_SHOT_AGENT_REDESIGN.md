# Gorgon「一句话交付结果」体验重构 V1 — 唯一执行说明

> 2026-10-23 · 工作分支：`feat/one-shot-agent-experience-v1`（从 `feat/v3l-pc-agent-controller` @ `8a407d7` 创建）。
> 此文档是本分支的单一任务上下文。禁止在 master、旧 V3K/V3J、其他功能分支同时开发；不重写整个仓库、不破坏用户已有本地数据。

## 0. 产品北极星 / 停止条件

用户表达最终目的 → 自动执行**已授权、低风险、能力范围内**的工作 → 给出可复核的真实成果；仅在权限、信息不足或高风险操作时请用户介入。**提交一次不需要再点「运行任务」或选 Skill**。用户永远不必读 JSON、手工选择工具或自行猜测错误原因。

**停止条件**：下面六个验收场景在真实 APK + 实际网络/离线环境中通过；有可追溯 commit、截图和真实执行日志。没有真实执行能力的动作明确标记不可用；绝不把「创建任务」「启动 WorkBuddy」「生成模板」冒充真实业务目标已完成。

## 1. 仓库核验后的问题根因（以代码为准）

1. `app/src/screens/WorkbenchHome.jsx` 的 `submit()` 只调用 `onCreateTask` 再 `onOpenTask`，用户要去 `TaskDetailScreen.jsx` 按「运行任务」；`app/src/App.jsx` 中 `runTaskEngine` 已存在但没有在新建时调起。这是明确的多余交互。
2. `app/src/workbench/task-router.js` 是关键词规则命中器，固定 5 类技能、`MAX_SKILLS_PER_TASK=3`，不是真正的多步目标分解；`runTask` 遇无法匹配目标会返回 `executed:false`。
3. `app/src/workbench/task-runner.js` 已具备部分成功留存和失败代码，应该复用而非重造；但仍需要新建任务自动触发、依赖关系、失败恢复、执行结果真实性核验。
4. `scripts/agent-gateway.mjs` 的远端执行器以白名单只读为主；`workbuddy.submitTask` 在 `scripts/agent-adapters/workbuddy-adapter.mjs` **仅支持 4 种真实只读操作**。不能将“已连接电脑/已启动 WorkBuddy”解释为已替用户开展任意工作。
5. `docs/V3L_PC_AGENT_CONTROLLER_GUIDE.md` 明确局域网连接、Codex/WorkBuddy 限制及真实 APK 尚需真机确认；从代码推断的“已实现”不得写成“真机验收通过”。
6. `readme.md` 与分支的版本说明可能滞后；以所选分支源码、CI、设备运行事实为准，勿直接沿用旧 README 的“最新版本”宣称。

## 2. 全新交互（P0 必须完成）

**首页仅一个主入口**：「告诉 Gorgon，你想完成什么？」下面展示**正在执行 / 需要你确认 / 最近成果**，搜索、任务列表和其他管理功能放二级入口。输入框的提交文案为「开始处理」。

### Submit → Start 原子化编排
- 创建任务并持久化后，**同一个提交动作**立即调度已授权的低风险本地/只读能力；无需第二次点「运行任务」。保留直达任务详情，但详情是进度/成果页，不是二次执行前置页。
- 用 `submissionId/idempotencyKey` 去重，防止用户连击、组件重渲染、断网重试、APP 重启后重复生成任务或副作用。相同 task/run ID 不重复消费已成功步骤。
- 无法识别目标时不悄悄返回 `created/ready`：用普通中文提示「我还不能直接完成这类操作」，给出最接近的可执行动作或一个**必要的**澄清问题，不要求用户理解 Skill 名称。
- 对任务步骤分级：①可自动执行（只读、整理、生成草稿）；②需明确批准（外发、修改远端文件、安装、购买、删除、涉及账户或隐私的动作）；③未支持/不可达 → BLOCKED 并说明替代方式。
- 可以取消；取消后不得偷偷复活；再次点击「继续」应从明确的失败/未完成步骤恢复，不覆盖已完成产物。

### 清晰的结果态
UI 统一使用 `规划中 / 执行中 / 需要确认 / 已完成 / 部分完成 / 暂不可用 / 已取消`；
每一条成果必须包含：**完成了什么、成果在哪里、还有什么没做、依据/来源、下一步可做什么**。技术日志折叠在「诊断信息」中。
“搜索不可用”≠“已搜索完成”，“本地模板”≠“查询过真实资料”，“启动智能体”≠“智能体执行并交付”。

## 3. 底层执行架构（P1）

将用户语言映射到显式 `Goal -> Plan -> Step -> Capability -> Evidence` 契约。先在现有 Router/Runner 外增加小型 orchestrator，不推倒 task-store 和 Gateway：
- `Plan`: goal / constraints / expectedDeliverable / steps[] / approvalPolicy。
- `Step`: id / dependsOn[] / executor / input / status / attempt / maxAttempts / idempotencyKey / evidence[] / outputRef / errorCode。
- 每个 executor 需要 `capability`、`isAvailable`、`preflight`、`run`、`verify`、`cancel` 接口，先支持已验证的本地技能和只读电脑操作。
- 启动前执行能力预检：设备是否可达、配置是否存在、授权是否有效、是否联网、超时/额度是否足够。不得把健康检查 `HTTP 200` 当成目标任务成功。
- 短暂网络失败使用**限次、指数退避**重试；认证/未授权/不可支持的错误不盲重试。UI 给出人话错误、用户可操作的恢复入口。
- 引擎由持久化队列管理，单任务步骤执行有 deadline、cancel 信号、重复提交去重；APP 被系统挂起时不承诺继续执行。要真正后台执行，需受控电脑/服务器的常驻执行者；恢复时先对账，再决定重试，不自动重演外部副作用。
- 搜索必须使用真实且可追溯的数据源，显示 URL、来源、时间、检索失败范围；匹配与过滤用户条件。无法联网时提供**明显标注**的离线草稿，并说明未完成的实时检索；不能与搜索实际结果混为一谈。
- WorkBuddy 写入/发消息与通用电脑操作**不是已验证能力**。优先利用正式公开、授权的能力；如不存在则保留 BLOCKED，不反向工程绕过权限、不在移动端下发任意 shell 命令。
- 敏感数据/密钥只留在受控端，网关默认 loopback；手机局域网连接使用配对密钥、撤销及最小权限，不直接暴露无认证服务到公网。

## 4. 优先级 / 一条分支逐步交付

**P0：消灭二次点击、修复真实失败路径（先完成）**
1. 记录基线：源码/现有测试、`createTaskFromGoal` 与 `runTaskEngine`、任务详情状态、API 注入和离线行为。
2. 首页新建时自动执行可运行低风险技能；任务详情首次进入即可见真实状态，历史手动任务仍可手动运行。不可重复执行、失败可见；不要绕过用户确认。
3. 搜索服务故障呈现具体原因；用户请求「找活动」时不要伪造本地模板为实时信息；无联网的本地整理场景直接产出。
4. 追加针对重复点击/unknown/离线/重启/取消的自动化回归测试。

**P1：让结果真正有用**
5. 重构成果页：中文摘要、结构化卡片、来源、可点击成果、成功/未完成步骤；不能生成“能看不能用”的空模板。
6. 任务编排支持依赖和明确的预检；先打通一个实际生活场景（推荐：搜索真实活动→筛选→给出来源→生成可保存清单），而不是同时添加 10 种半成品 Agent。
7. 失败自动补救只针对安全、幂等的步骤；必要时引导用户连接电脑、补授权，修好后继续而非重新开始。

**P2：电脑执行与 UI 精简**
8. 完成最小真实 PC 动作闭环：明确工作目录、受控文件产出、权限确认、回传结果与产物；做不到的功能不上首页。
9. 首页由功能宫格改成目标输入 + 进度 + 成果；导航简化成「首页 / 任务 / 资料 / 我的」。原有活动、地点、日程、项目数据保留并从次级入口访问。
10. 最终由 Android 真机验证 APK：不是网页截图或单测通过就宣称完成。

## 5. 6 个必须通过的验收剧本

1. 输入「帮我整理一份比赛报名资料清单」→ 一次提交后生成可阅读、保存的本地清单；**没有**二次运行按钮点击、没有错误线上搜索。
2. 输入「找上海未来 7 天真实的免费 AI 活动并整理参加清单」→ 自动检索、匹配日期和城市、给出处、清单；如缺实时来源，则返回**明确的部分完成/无法查询**，不伪造。
3. 连续双击提交/关闭重开 APP → 一个 task/run、不出现重复任务，已有结果留存。
4. 搜索后端断网、Codex 未授权、WorkBuddy 不支持写任务 → 分别显示可以理解的原因 + 可恢复操作，不出现“成功”假状态。
5. 混合任务中一个步骤失败、另一个成功 → 结果正确记录**部分完成**，失败部分可单独重试，不重做成功部分。
6. 真机完成「创建→自动执行→结果→保存/复查」完整链路；测试报告列出机型、Android、APK versionCode、签名、网络、实际结果、PASS/FAIL/BLOCKED 与截图。

## 6. 开发纪律 / 输出格式

- **唯一分支**：`feat/one-shot-agent-experience-v1`。后续 AI 每次先拉此分支，先读本文件与涉及源码；不必把长对话当需求。
- **不大改**数据库结构、不清用户数据、不重建项目、不并行分叉；修改尽量分小 commit。
- **尽量云端构建/运行测试**，本地真机仅作最终真实验收；任何依赖电脑设备、真机、签名或外网的测试缺失都报 BLOCKED。
- 每个阶段必须给出：`提交 SHA / 实际修改路径 / 所执行测试 / 结果 PASS-FAIL-BLOCKED / 尚未打通的真实能力 / 下一步最短动作`。
- 合并 master 和 Release 必须在验收完成后另行处理，不得默默自动合并或发布。
