# F. 回归风险与验收标准

## F1. 回归风险矩阵

| 风险 | 等级 | 触发阶段 | 影响 | 缓解措施 |
|---|---|---|---|---|
| **E2E 导航钩子断裂**：改造后 `data-workbench-nav`(6) / `data-gg-nav`(5) / tabbar「搜索」文案缺失，`e2e_workbench_shell.mjs` + `e2e_v1_frontend.mjs` + 两个 android E2E 全红 | **高** | 阶段 5 | 测试全红，无法判断真实缺陷 | 保留隐藏兼容层（沿用 `App.jsx:106` 既有模式）；或同 PR 更新 E2E 并说明 |
| **E2E 文案断言断裂**：阶段 3 改文案会命中大量 `innerText.includes(...)` 断言 | **高** | 阶段 3 | 数十条断言失败 | 改文案与改断言同一提交；先用 `grep -n "includes("` 列出全部受影响断言 |
| **DOM 被折叠删除**：阶段 4 把区块移入 `<details>` 时误删节点，`querySelector` 返回 null | **中** | 阶段 4 | 局部断言失败 | 折叠只改可见性，**DOM 全保留**（`<details>` 内容在 DOM 中）；改完立即跑 §40-42/§71-72 |
| **触控尺寸放大导致布局溢出**：Chip 29→40、Button sm 36→44 后横向溢出/换行错位 | **中** | 阶段 2 | 视觉破版（尤其 360px 窄屏） | 逐屏目视核对；`flexWrap` 与 `min-width:0` 检查 |
| **字体栈变更导致字重/字距变化**：去 CDN 后中文用系统字体 | **低** | 阶段 0 | 视觉微差，不影响功能 | 只影响字体渲染，截图对比 |
| **软键盘避让改动影响桌面** | **低** | 阶段 7 | 桌面布局异常 | `enterKeyHint`/`inputMode` 在桌面无副作用；视觉避让仅移动端断点生效 |
| **危险操作加确认阻塞 E2E 点击** | **中** | 阶段 6 | E2E 点删除后卡住 | 确认层必须有稳定 `data-testid`，并同步更新 E2E 点击序列 |
| **状态机/持久化被误改** | **高** | 任意 | 数据损坏 / 非法流转 | 硬约束：禁止修改 `workbench/task-model.js`、`store/*-repository.js`；单测 333 项为护栏 |
| **`reports/`、`docs/` 之外的方案文件混入业务代码** | 低 | 全流程 | 交付物与代码混淆 | 设计交付物集中在 `docs/workbench/ui-redesign/`，不触碰 `app/src/**`（阶段 0 起才改） |

## F3. 验收标准（按交付物）

### A 问题清单 → 验收
- 每条 P0/P1 问题在修复后能被**复述的复现步骤**验证（点击哪里、看到什么变成什么）。

### B 信息架构 → 验收
- 底部导航 **4 项**，无"更多"抽屉；抵达任一页面**不超过 2 次点击**。
- 9 项抽屉中每一项都能在新的「我的」里找到，**无功能丢失**（逐项对照 `E_CODEX_PLAN.md` §5 映射表）。
- 「发现 → 创建行动 → 安排时间 → 执行 → 记录」在真机上可连续走通，无死路。

### C 设计规范 → 验收
- 全项目**无硬编码 `#047857`/`#9A6300`/`#00A277`/`#1D4ED8`**（改为 `--success-ink`/`--warning-ink`/`--info-ink`）。
  **基线（本次实测，`app/src`，2026-10-13）**：44 处 · 13 个文件 → 目标 **0 处**。
  验证：`grep -rn "#047857\|#9A6300\|#00A277\|#1D4ED8" app/src --include=*.jsx | wc -l` 应为 `0`。
- 可点元素热区 **≥44px**（主操作 ≥48px）：用一个自动化脚本扫描 `padding/fontSize` 组合，输出违规清单，目标为 0。
- 文字对比度：正文 ≥ 4.5:1，次要 ≥ 3:1（用取色工具抽检 10 个组合）。
- 中文界面**无英文技术词**：`grep -rniE "schema|localstorage|json\.stringify|http |provider|pipeline" app/src/screens`
  **基线**：28 处 → 目标：命中项全部位于"技术详情 / 关于与诊断"折叠区内。

### D 高保真原型 → 验收
- `docs/workbench/ui-redesign/prototype/index.html` 可直接打开，4 个 tab 可点、任务行可进详情、今天可切周视图。
- 原型中每个页面都带**实现状态标注**；未实现项（周视图、地图、求职管理屏）显式标注，不以演示数据冒充。

### E Codex 清单 → 验收
- 每个阶段有 DoD 与"不做"边界；阶段间可独立合并；无阶段跨越修改状态机/持久化。

### F 本文件 → 验收
- 每次提交跑完 F2 的 7 个门禁，结果记录进 `docs/workbench/DELIVERY_STATE.md`。

## F4. 用户场景真机验收（沿用 V2.2 Issue 清单）

| 场景 | 步骤 | 通过判定 |
|---|---|---|
| A 活动参加 | 发现 → 搜"周末 AI 活动" → 查看来源 → 加入行动 → 安排 10/14 14:00 → 开始执行 → 记录 → 完成 | 6 步均可在真机完成；结果区显示中文摘要；时间线留痕 |
| B 求职/学习 | 发现机会 → 保存 → 创建项目/任务 → 跟踪进度 | 项目详情可见任务与进度；状态机无非法流转 |
| C 地推走访 | 我的→走访地点 → 记录地点 → 标记已去/未去/需复访 → 记笔记 → 查看后续安排 | 状态变更持久化；重启后仍在 |
| D 单手操作 | 单手拇指可触达底部导航与页面主操作 | 主操作在屏幕下半区；无 <44px 关键热区 |
| E 断网恢复 | 飞行模式 → 操作 → 恢复网络 | 不崩溃；错误提示为中文且可重试；本地功能不受影响 |

## F5. 明确不做（防止 scope 蔓延）

1. 不重构状态机、不改数据结构、不改持久化键名。
2. 不接入真实地图/路线服务（保持占位并如实标注）。
3. 不实现求职管线专用管理屏（不在本次范围）。
4. 不引入新的 UI 组件库/图标库/CSS 框架。
5. 不做国际化多语言（仅中文优先）。
6. 不美化式重写业务逻辑——所有改动必须对应 A 文件里的具体问题编号。
